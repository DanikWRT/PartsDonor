# PartsDonor — архитектура и стек (по ресерчу)

> B2B-маркетплейс б/у запчастей смартфонов между мастерскими.
> Решение по итогам свежего ресерча (архитектура, стек, платежи, доставка).

---

## 1. Главный факт выбора стека

**InvenTree — Python/Django/DRF с REST API (OpenAPI, стабильные эндпоинты `part/`, `part/category/`, `stock/`, `bom/`, `company/`, SalesOrder/PurchaseOrder).** Уже развёрнут локально на `127.0.0.1:8000`.

=> рыночный слой выгоднее строить в **Python (FastAPI)** — минимум интеграционного трения, переиспользование моделей InvenTree напрямую. Это решающий аргумент, а не «привычка».

---

## 2. Внешние интеграции (проверено по первоисточникам)

- **ЮKassa Безопасная сделка** (escrow): холд оплаты до 180 дней, выплата продавцу после подтверждения сделки (карты РФ, ЮMoney...). Официальный SDK `yookassa`.
  - ⚠️ НЕ путать с «ЮKassa для платформ / сплитование»: тот требует оборот ≥3 млн ₽/мес и платит продавцу сразу. Для B2B-эскроу — именно **Безопасная сделка**.
- **СДЭК API v2**: официальная бесплатная интеграция. SDK `aiocdek` (Python async): создание заказа, расчёт тарифа, webhooks. Эндпоинты стабильны: orders, tariffs, calculators, webhooks (ORDER_STATUS).

---

## 3. Сравнение трёх вариантов архитектуры

### (а) Самописный backend-слой поверх InvenTree REST ✅ РЕКОМЕНДОВАН
| Критерий | Оценка |
|---|---|
| Скорость | Высокая. Каталог/склад/BOM/поставщики уже в InvenTree. Пишем: auth, листинги, сделки, эскроу, доставку, «развёртку». |
| Гибкость UI | **Максимальная** — интерактивная развёртка телефона (галочки = Part id из BOM) полностью наша. |
| Стоимость | Низкая (MIT, self-hosted, бесплатные API). |
| Масштаб | Хорошая: FastAPI+Postgres горизонтально, InvenTree отдельно. |

### (б) Готовые headless-CMS (Strapi/Medusa/Saleor/Vendure/Directus) — ОТБРОШЕНО
Каталог уже покрыт InvenTree → второй «каталог» = **дублирование данных** и синхронизация. «Развёртку» всё равно пишем сами. Лишняя сущность.

### (в) Полная самописная — ОТБРОШЕНО
Заново писать каталог/склад/BOM/поставщиков — месяцы лишней работы. Вариант (а) даёт ту же гибкость и масштаб за долю времени.

## 4. Рекомендуемая архитектура (гибрид)

```
[Frontend SPA: Vite + React + TS]
        │ REST
        ▼
[PartsDonor API: FastAPI]  ← маркетплейс-логика (листинги, сделки, эскроу, доставка)
        │ тонкий httpx-клиент (НЕ SDK inventree — он ломается между версиями)
        ▼
[InvenTree REST API 127.0.0.1:8000]  ← каталог/склад/совместимость
        │
        └ [Postgres (InvenTree)]
[Postgres (PartsDonor, отдельная БД)]  ← только маркетплейс-состояние
```

### Разделение данных
- **InvenTree (источник истины):** Part, BOM (донор = assembly + дети-компоненты), StockItem (физическая деталь на полке), Company (мастерская), StockLocation, SalesOrder/PurchaseOrder.
- **Postgres PartsDonor (только маркетплейс-состояние):** статус листинга (active/sold), provenance-текст, рейтинги, сделки и их эскроу-статус, платежи, доставка. Ключи — по `part`/`stock_item` id из InvenTree.
- Интерактивная «развёртка»: hotspot на картинке донора → Part id из BOM. Отдаётся из нашего слоя, данные — из InvenTree.

### Детали интеграций
- **ЮKassa Безопасная сделка:** создать сделку на холд → webhook `payment.succeeded` → при подтверждении обеих сторон выплата продавцу / возврат покупателю. Проверять HMAC-подпись. SDK `yookassa`.
- **СДЭК v2:** `aiocdek` — тариф, заказ, квитанция, webhook `ORDER_STATUS` для трекинга в сделке.
- **InvenTree:** тонкий httpx-клиент с `Authorization: Token <key>`. Нюансы:
  1. auth — InvenTree `ApiToken` (не DRF authtoken);
  2. GET-листы отдают **или** массив, **или** `{"results":[...]}` — нормализовать;
  3. BOM родителя требует `assembly=True`.

## 5. Конкретный стек

| Слой | Выбор | Обоснование |
|---|---|---|
| **Фронт** | **Vite + React + TypeScript** | Mobile-first SPA, полный контроль над «развёрткой» (React, SVG/hotspot). Next.js избыточен (нет SEO-приоритета у B2B-площадки). |
| **Бэк** | **FastAPI (Python)** | Тот же язык, что InvenTree → интеграция без трения; SDK yookassa/aiocdek. |
| **БД** | **PostgreSQL (отдельная)** | Для маркетплейс-состояния; ключи по InvenTree-ид. |
| **Платежи** | **ЮKassa Безопасная сделка** + `yookassa` | Холд до 180 дней, выплата после сделки, HMAC-вебхуки. |
| **Доставка** | **СДЭК API v2** + `aiocdek` | Тарифы, заказы, ПВЗ, webhooks. |
| **Каталог/склад** | **InvenTree (MIT, Docker)** | Уже развёрнут, источник истины. |

---

## 6. Итог

- **Рекомендация: вариант (а)** — собственный тонкий FastAPI-слой поверх стабильного REST InvenTree + отдельная Postgres для маркетплейс-состояния. Гибрид даёт максимум гибкости UI (развёртка с галочками) за минимум времени и денег.
- **Ключевой нюанс платежей:** эскроу-семантику даёт именно «Безопасная сделка», не «ЮKassa для платформ» (тот — от 3 млн ₽/мес и платит сразу).
